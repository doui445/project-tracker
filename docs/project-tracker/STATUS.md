# STATUS — project-tracker

## Where it stands

`project-tracker` is a published Claude Code plugin at **v0.3.0**. The four
build workstreams are done:

1. **C1 — standalone public repo** (`github.com/doui445/project-tracker`).
2. **C2 — full English translation** of the shipped skill, hooks, portfolio
   generator and generated HTML (machine values left untranslated).
3. **C3 — portfolio rework**: one unified `PORTFOLIO.html` aggregating every
   tracked project across all scopes, written to the folder set in
   `~/.claude/project-tracker/portfolio.txt`, regenerated by a deterministic
   `PostToolUse` hook — no dependence on Claude's judgment.
4. **C4 — plugin wiring**: `.claude-plugin/{plugin,marketplace}.json` +
   `hooks/hooks.json` bundle the skill and its three hooks; the
   `install-project-tracker.sh` path is kept in parallel; hook scripts are
   self-relative so they work in all three modes (plugin / skills-dir / script).

### What works

- `SessionStart` hook detects tracked / new / excluded projects within the
  `scopes.txt` roots.
- Bootstrap creates the nine standard files plus optional
  `ARCHITECTURE.md` / `GLOSSARY.md`.
- Continuous upkeep of `STATUS.md` + append-only logs.
- Optional GitHub repo automation via `gh`.
- Optional Apple Reminders sync (`PostToolUse`, once per session per project).
- `/project-tracker:config` command (plugin install only).
- `test_plugin_manifest.py` + the hook/portfolio test suites pass.

### Known gaps

- Output language is effectively fixed to English — the user cannot choose.
- Version is bumped in `plugin.json` / `marketplace.json` but there are no
  git release tags.
